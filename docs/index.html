What SwiftFilez actually does

SwiftFilez helps you answer a practical question: “What is this file or release artifact, what is inside it, and can I reason about it safely?”

It combines normal file operations with artifact-aware inspection. That means the same tool can calculate a SHA-256 digest, identify a Python wheel, recognize a Docker or OCI archive, discover a CycloneDX or SPDX SBOM, and produce structured output for automation.

Local-first by design. Core artifact inspection does not require an account, API key, SaaS subscription, or network connection.
QUICK START

Install SwiftFilez

Swift currently installs from the repository. Python 3.10 or newer is supported.

git clone https://github.com/mergemaven11/swift.git
cd swift
python -m venv .venv

# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.\.venv\Scripts\Activate.ps1

python -m pip install -e .
swf --version
swf doctor

swf doctor is the fastest way to confirm that the local environment is healthy before using Swift in a script or pipeline.

FILE INSPECTION

Inspect a normal file

Use the main CLI when you want file metadata and integrity information.

swf inspect ./release/app.bin
swf hash ./release/app.bin
swf scan ./release --json

This is useful before upload, before deployment, when comparing artifacts between environments, or when you need a deterministic hash for an audit trail.

ARTIFACT INTELLIGENCE

Look inside complex artifacts

The artifact command recognizes software-oriented formats and can recursively inspect interesting nested content without sending the artifact anywhere.

swf-artifact inspect release.zip
swf-artifact inspect release.zip --recursive
swf-artifact inspect image.tar -r --json
swf-artifact inspect bundle.zip -r --max-depth 5

Recursive inspection can surface nested archives, dependency manifests, SBOMs, provenance documents, package formats, and container metadata. Each inspected artifact receives a SHA-256 identity so a result can be tied back to the exact bytes that were analyzed.

release.zip ↳ app.whl ↳ bom.cdx.json ↳ provenance.json ↳ package.json
SBOM INTELLIGENCE

Turn SBOM files into normalized findings

Swift recognizes CycloneDX and SPDX SBOMs and normalizes package/component information into a common model. That makes later policy checks possible without requiring every downstream tool to understand every SBOM flavor.

  • Name and version — identify the component being described.
  • Type — preserve package/component type when available.
  • PURL — retain package URLs used to correlate software identities.
  • License — capture license information when the SBOM provides it.
  • Quality findings — flag useful gaps such as missing versions or PURLs.

Swift does not claim that “an SBOM exists” means “the software is secure.” An SBOM is evidence about contents; policy and vulnerability interpretation are separate concerns.

REAL-WORLD EXAMPLES

Where Swift helps

PLATFORM ENGINEER

A release arrives as one ZIP file.

You do not want to manually unzip it, inspect every nested package, open an SBOM, and then build a separate inventory.

swf-artifact inspect release-2026.09.zip --recursive --json

Swift identifies the outer archive, hashes it, discovers interesting nested artifacts, normalizes SBOM content, and gives the pipeline one machine-readable result.

RELEASE ENGINEER

You need to prove a deployment artifact did not drift.

swf manifest build ./dist --output manifest.json
swf manifest verify ./dist manifest.json

The manifest becomes an integrity contract for the release directory. Changed, missing, or unexpected files can be detected before promotion.

DEVSECOPS

You receive an OCI/Docker archive with an SBOM.

Swift can recognize the container artifact and related SBOM/provenance material locally. Future policy layers can build on the same normalized result rather than reimplementing parsing for each artifact type.

CI/CD

Use Swift as a pipeline primitive

Human-readable output is useful at a terminal. Automation needs stable JSON and meaningful exit codes. Swift supports both patterns.

# Example CI step
swf doctor --json
swf scan ./dist --json
swf-artifact inspect ./dist/release.tar --recursive --json

A useful pattern is to save JSON output as a build artifact, feed it into a later policy step, and keep the SHA-256 identity alongside the release being promoted.

AUTOMATION OUTPUT

Prefer JSON when another tool is reading Swift

swf-artifact inspect app.whl --json
swf-artifact inspect release.zip --recursive --json

JSON is intended for scripts, CI jobs, artifact reports, and future integrations. Human-friendly rendering may change visually over time; machine-readable fields should be treated as the integration surface.

SAFETY MODEL

Swift treats artifacts as untrusted input

Archives can be hostile even when they look ordinary. Swift's recursive analysis uses explicit boundaries rather than blindly extracting everything.

  • Recursive depth is bounded and configurable.
  • The number of interesting child artifacts is bounded.
  • Archive members above the configured safety ceiling are skipped.
  • Temporary inspection avoids writing archive paths directly into your working tree.
  • Core inspection remains local and does not upload artifacts to a remote service.
Important: format recognition is not malware scanning. Do not execute an untrusted artifact simply because Swift successfully identified it.
TROUBLESHOOTING

Common problems

swf: command not found

Activate the virtual environment where Swift was installed, then run python -m pip install -e . again from the repository root.

swf-artifact: command not found

Make sure you are on a version containing the artifact registry and reinstall the package so the new console entry point is registered.

An archive shows fewer children than expected

Recursive inspection intentionally keeps only artifact-relevant children and applies depth, count, and size safety limits. Increase --max-depth or --max-children deliberately when needed.

I need to know whether my environment is healthy

Run swf doctor --json. It is designed as a quick local/CI diagnostic.

ROADMAP

Where artifact intelligence goes next

The goal is not to turn Swift into a paid cloud service. The core stays useful offline, while optional integrations can extend it.

  • Signed artifact and manifest verification with Sigstore/Cosign-compatible workflows.
  • OPA/Rego policy evaluation over normalized artifact findings.
  • Plugin discovery for additional package and metadata formats.
  • Optional S3, GCS, and Azure Blob adapters.
  • OpenTelemetry instrumentation with local/console-friendly defaults.
