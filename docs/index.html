START HERE

What SwiftFilez actually does

SwiftFilez helps you answer a practical question: “What is this release artifact, what is inside it, and does it meet the rules I expect before I promote it?”

It combines normal file operations with software-artifact intelligence. The same tool can calculate SHA-256 identity, recognize packages and container archives, discover CycloneDX or SPDX SBOMs, normalize component data, and enforce deterministic acceptance policy.

Local-first by design. Core inspection and policy evaluation do not require an account, API key, SaaS subscription, or network connection.
QUICK START

Install SwiftFilez

Swift currently installs from the repository. Python 3.10 or newer is supported.

git clone https://github.com/mergemaven11/swift.git
cd swift
python -m venv .venv

# macOS / Linux
source .venv/bin/activate

# Windows PowerShell
.\.venv\Scripts\Activate.ps1

python -m pip install -e .
swf --version
swf doctor
swf readiness

swf doctor checks the local environment. swf readiness shows which beta acceptance capabilities are present in the installed build.

FILE INSPECTION

Inspect a file or software artifact

swf inspect ./release/app.bin
swf inspect ./release/package.json --json
swf hash ./release/app.bin
swf scan ./release --json

Normal inspection returns file identity plus artifact format information when Swift recognizes the file as a software-oriented artifact.

ARTIFACT INTELLIGENCE

Look inside complex artifacts

Recursive inspection discovers interesting nested artifacts without blindly unpacking an archive into your working directory.

swf inspect release.zip --recursive
swf inspect image.tar -r --json
swf inspect bundle.zip -r --max-depth 5 --max-children 200

Swift can surface nested archives, dependency manifests, SBOMs, provenance documents, package formats, and container metadata. Every inspected artifact receives SHA-256 identity.

release.zip↳ app.whl↳ bom.cdx.json↳ provenance.json↳ package.json
SBOM INTELLIGENCE

Turn SBOM files into normalized evidence

Swift recognizes CycloneDX and SPDX SBOMs and normalizes package/component information into a common model for inspection and policy.

  • Name and version — identify the component being described.
  • Type — preserve package/component type when available.
  • PURL — retain package URLs used to correlate software identities.
  • License — capture license information when supplied.
  • Quality findings — surface useful gaps such as missing versions or PURLs.

An SBOM is evidence about software contents; its existence alone does not mean an artifact is secure.

POLICY GATES

Turn artifact evidence into an acceptance decision

Swift's beta policy engine is deliberately small and deterministic. Policies are local JSON files, so a team can version them beside application or platform code.

swf policy check release.zip --policy examples/uat-policy.json
swf policy check release.zip --policy release-policy.json --json

A compliant artifact exits with code 0. A policy rejection exits with code 2, making it straightforward to stop a CI promotion without confusing a rejected release with a broken Swift installation.

Example controls: require an SBOM family, require component versions, require package URLs, deny artifact families, or cap findings/warnings.

REAL-WORLD EXAMPLES

Where Swift helps

PLATFORM ENGINEER

A release arrives as one ZIP file.

Instead of manually unpacking it and opening every metadata file:

swf inspect release-2026.09.zip --recursive --json

Swift creates one machine-readable view of the interesting nested artifacts and normalized SBOM evidence.

RELEASE ENGINEER

You need to prove a deployment artifact did not drift.

swf manifest build ./dist --output manifest.json
swf manifest verify ./dist manifest.json

The manifest acts as an integrity contract for the release directory.

DEVSECOPS

You need a release gate that does not depend on another SaaS account.

swf policy check release.tar --policy release-policy.json

Swift inspects locally, evaluates locally, and returns a CI-friendly acceptance decision.

CI/CD

Use Swift as a pipeline primitive

swf doctor --json
swf inspect ./dist/release.tar --recursive --json
swf policy check ./dist/release.tar --policy release-policy.json --json

Save JSON inspection output as a build artifact, keep its SHA-256 identity alongside the release, and use the policy command as a promotion gate.

AUTOMATION OUTPUT

Prefer JSON when another tool is reading Swift

swf inspect app.whl --json
swf inspect release.zip --recursive --json
swf readiness --json

Human-friendly rendering can evolve visually. JSON is the intended integration surface for scripts, CI jobs, and artifact reports.

SAFETY MODEL

Swift treats artifacts as untrusted input

Recursive analysis uses explicit boundaries instead of unrestricted extraction.

  • Recursive depth and interesting-child counts are bounded.
  • Per-member size, scanned-entry count, and total-byte budgets limit archive work.
  • Temporary inspection avoids writing archive paths directly into the working tree.
  • Core inspection and policy evaluation remain local.
Important: format recognition is not malware scanning. Do not execute an untrusted artifact simply because Swift identified it.
TROUBLESHOOTING

Common problems

swf: command not found

Activate the virtual environment where Swift was installed, then run python -m pip install -e . again from the repository root.

An archive shows fewer children than expected

Recursive inspection intentionally retains artifact-relevant children and applies safety limits. Increase --max-depth or --max-children deliberately when needed.

My policy command exits with 2

That means Swift ran successfully but the artifact did not meet the policy. Read the returned violations to see which acceptance rule failed.

I need to know whether this build is UAT-capable

Run swf readiness --json and follow the scenarios in docs/UAT.md.

AFTER UAT

What comes after the beta acceptance scope

UAT has a fixed scope so the finish line does not move forever. These are enhancements, not blockers for the current beta:

  • Signed artifact and manifest verification with Sigstore/Cosign-compatible workflows.
  • Optional OPA/Rego evaluation for organizations already using OPA.
  • Plugin discovery for additional artifact analyzers.
  • Optional S3, GCS, and Azure Blob inputs.
  • OpenTelemetry instrumentation with local/console-friendly defaults.
